# Lead Check

Веб-приложение для проверки и оценки лидов Worrki. Принимает JSON заявки, ищет публичные сведения о человеке и компании, сверяет их с заявкой и показывает объяснимую оценку.

## Как пользоваться

1. Вставьте JSON в поле `INPUT.JSON` или нажмите «Загрузить пример».
2. При необходимости нажмите «Форматировать».
3. Исправьте ошибки, если статус поля — `INVALID`.
4. Нажмите «Проверить лид». Приложение проверит данные на сервере, выполнит поиск публичных источников и покажет результат анализа.

Для проверки нужны `lead_id` — положительное целое число, а также непустые строки `name` и `company_name`. Остальные поля необязательны; дополнительные поля заявки сохраняются.

Для каждого сведения отчёт показывает статус, цитату и ссылку на доступную страницу. Исторические упоминания, частичные совпадения, противоречия и отсутствие публичного подтверждения отмечаются отдельно. Недоступные страницы не используются как доказательство. Проверка источников не является гарантией подлинности сведений: менеджер может открыть страницу и сверить её актуальность.

`Lead score` показывает ценность лида по найденным признакам, `verification confidence` — покрытие проверки источниками. Баллы начисляются по пяти фиксированным критериям: компания и местонахождение (до 20), профиль бизнеса (до 30), доступ к кандидатам (до 20), полномочия человека (до 20) и международное направление (до 10). Страница без независимого подтверждения даёт половину баллов за найденный признак. Сама заявка баллов не приносит. Результат всегда содержит HOT/WARM/COLD и score от 0 до 100. При низкой полноте проверки `review_required` и комментарий объясняют, что низкий score не доказывает ложность заявки. `CRM OUTPUT` показывает JSON для возможной передачи в CRM.

## Запуск

Требуются Node.js, npm и ключ OpenAI API. Создайте `.env.local` в корне проекта:

```env
OPENAI_API_KEY=your_api_key
```

Файл `.env.local` исключён из Git. Ключ используется только серверным маршрутом.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

## API

`POST /api/analyze` принимает JSON лида. После валидации возвращает `200` и поток NDJSON: события `progress` с текущей стадией, затем `verified` с идентификатором лида, проверками и оценкой либо `error` с безопасным сообщением. Стадии соответствуют фактическим шагам сервера: поиск, получение страниц, разбор цитат, проверка результата и расчёт баллов. Искусственных задержек нет. После начала потока ошибки передаются событием, HTTP-статус уже не меняется.

До начала потока неверный JSON возвращает `400`, неподходящие данные лида — `422`, слишком большой запрос — `413`. Редактирование входа отменяет текущий запрос и очищает предыдущий результат.
